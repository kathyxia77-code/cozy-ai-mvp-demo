1. 基础信息
一句话摘要

不是重新做一个聊天机器人，而是将已有原型建设成 Momcozy 面向用户的智能服务入口，使品牌从“销售母婴产品”进一步延伸为“持续提供智能母婴服务”
核心业务问题
Momcozy 已经拥有母婴硬件、App、用户记录、设备数据、专业内容和服务资源，但这些能力目前主要以独立页面、设备功能、说明资料和人工服务的形式存在。

2. 需求背景

Momcozy 已经拥有母婴硬件、App、用户记录、设备数据、专业内容和服务资源，但这些能力目前主要以独立页面、设备功能、说明资料和人工服务的形式存在。用户购买产品后，Momcozy 与用户之间仍以单点功能和被动答疑为主，没有形成贯穿孕期、产后和育儿阶段的连续服务关系。
当前 MomCozyAgent 与 MomCozyApp 已经验证了统一自然语言入口、连续上下文、业务数据读取、工具执行、私有知识库、结构化结果展示的技术可行性。本次立项不是重新做一个聊天机器人，而是将已有原型建设成 Momcozy 面向用户的智能服务入口，使品牌从“销售母婴产品”进一步延伸为“持续提供智能母婴服务”。

基于竞品对比定义的"Agent 架构 + 吸乳/睡眠/康复三域统一计划排期 + 情绪识别 + IBCLC/家庭协同"，Cozy AI 对话入口框架应该是"三合一融合入口"——既不是单纯的记录框，也不是单纯的咨询 Tab，而是：
                                             🎯 入口定位：「今日节奏」+「对话入口」融合框架

场景三： 新用户智能体对话引导
目的： 作为新用户，首次进入全局对话的操作第一条消息的指引。
设计意图：简单易操作。很快知道如何发送第一条消息，以及问什么问题。

[图片]

顶部 What's coming up next? 的消息框
前置依赖： 
1. 数据来源依赖：预测引擎依赖用户的历史记录数据生成预测——吸乳计划（Pumping Log，来自泌乳 Agent / 设备记录）、睡眠预测（Sleep Log，来自睡眠 Agent）。本组件自身不产生数据。
2. 预测服务依赖：由「预测日程 Epic PRD」提供的预测服务接口，输出下次吸乳 / 下次睡眠的预计时间。本需求单只消费接口结果，不定义预测算法。
3. 接口契约先行：预测日程 Epic 未交付前，双方需先冻结接口契约（请求参数、返回字段、空态 / 低置信度返回值格式），主入口按契约开发并联调，避免阻塞本 Epic 排期。
4. 冷启动条件：用户至少有 1 条有效吸乳或睡眠记录后，预测服务才返回有效结果；新用户（零记录）接口返回空态，按照空状态展示。
5. 时区：预测时间按用户设备本地时区返回与展示。

占位交互规则： 
1. 展示时机：仅在预测服务返回有效数据时展示；新用户 / 无记录 （接口返回空态）时组件展示为：。
2. 默认状态：常驻对话页顶部，默认收起为一行摘要（"What's coming up next?" + 最近一条预测文案，如 "Pumping in ~40 min"）；点击展开为卡片查看全部预测，再次点击收起。
3. 学习态（新用户 / 预测引擎未激活）：保留 "What's coming up next?" 圆角标题与展开 / 收起图标，默认展开，并在下拉消息区展示静默信息 "We are still learning your rhythm. Log your pumping & BB sleep to unlock schedule predictions."；不展示预测摘要、预测条目或主动 CTA。预测模型激活并返回有效数据后，才切换为预测消息。
4. 刷新规则：每次进入对话页时请求一次预测数据；会话进行中不轮询、不实时刷新；用户完成一条吸乳 / 睡眠记录返回对话页时触发一次刷新。
5. 异常处理：预测接口超时（>3s）或报错时静默降级——本次不展示组件、不打断对话，下次进入时重试；连续失败不上报用户，仅埋点记录。


6. 页面状态矩阵

6.1 定义与目的

页面状态矩阵用于明确每个页面或组件在不同前置条件、用户操作和系统结果下的展示内容、可执行操作、系统行为及异常处理方式。

Figma 原型主要展示关键画面，但正式产品还需覆盖授权状态、空状态、加载状态、生成状态、成功状态、失败状态、超时状态、Session 过期、医疗风险等中间状态。页面状态矩阵用于统一产品、设计、客户端、后端、Agent、QA 和合规团队的实现口径，避免各端根据静态原型自行推断。

页面状态矩阵与其他文档的关系：
1. 用户流程图：说明用户如何从页面 A 进入页面 B；
2. 页面状态矩阵：说明用户停留在某个页面时，各种条件下页面如何变化；
3. 接口文档：定义每个页面状态所依赖的请求参数、返回字段和错误码；
4. 测试用例：根据状态矩阵逐项生成验收步骤和预期结果。

6.2 隐私授权与首次激活状态矩阵

| 状态 | 触发条件 | 页面表现 | 用户可操作 | 系统行为 | 异常处理 |
| 未授权初始态 | 账号首次进入 Cozy AI Tab | 全屏展示 Cozie IP、能力卡；Privacy Statement 默认不勾选；Get Started 置灰 | 返回、查看协议、勾选协议 | 查询账号授权状态和当前协议版本 | 查询失败时保留当前页并支持重试 |
| 查看协议 | 点击 Privacy Statement | 展开协议弹层 | 阅读、关闭 | 记录协议展示事件 | 内容加载失败时展示加载失败提示 |
| 已勾选待激活 | 用户勾选协议 | 勾选框选中；Get Started 点亮 | 取消勾选、点击 Get Started | 暂不创建会话 | 无 |
| 激活中 | 点击 Get Started | CTA 显示加载状态并防止重复点击 | 等待 | 保存用户 ID、协议版本、授权时间和地区 | 保存失败时恢复可点击并提示重试 |
| 已授权 | 授权保存成功或账号历史已授权 | 跳过授权页，进入 Cozy AI 全局对话页 | 开始使用 | 拉取宝宝资料、新手状态和当前 Session | 单项数据失败按对应页面空态降级 |

6.3 全局对话与 Session 生命周期状态矩阵

| 状态 | 触发条件 | 页面表现 | 用户可操作 | 系统行为 | 异常处理 |
| 新用户空态 | 已授权、无历史消息 | 时区问候语、Forecast 学习空态、3 条提示问题、4 个快捷 Chips；不显示新对话按钮 | 点提示问题、输入、语音、点 Chip | 创建待激活 Session，拉取本地默认问题或 FAQ 推荐 | 推荐问题失败时使用内置默认问题 |
| 新对话空态 | 用户主动新建对话 | 清空消息，恢复新手引导结构；Forecast 默认收起 | 输入或选择提示问题 | 归档上一 Session，创建新 Session | 归档失败后台重试，不阻塞新会话 |
| 活跃会话 | 已发送至少一条消息 | 展示连续消息流；顶部出现新对话按钮 | 继续提问、滚动、执行卡片、新建会话 | 持续写入当前 Session | 消息保存失败先保留本地并重试 |
| 会话恢复 | 用户离开页面或杀掉 App 后返回，且 Session 未过期 | 恢复原消息位置和未完成任务状态 | 继续对话 | 从服务端恢复消息，并与本地草稿合并 | 恢复失败时显示重试，不直接清空消息 |
| Session 自动结束 | 当前 Session 超过 12 小时无活动 | 下次进入展示新对话空态；旧会话进入历史列表 | 新建对话、查看历史 | 生成主题摘要并归档 Session | 摘要失败时使用首条用户消息截断作为标题 |
| 历史会话抽屉 | 点击顶部历史入口 | 展示 Chat History、按最后活动时间倒序排列 | 打开、长按删除或恢复、关闭抽屉 | 分页读取会话摘要 | 请求失败时显示局部重试，不影响当前对话 |
| 历史会话恢复 | 选择历史记录 | 展示该会话消息，当前活跃会话状态保持 | 查看、恢复为当前会话 | 拉取完整消息；仅允许恢复未删除会话 | 内容不存在时提示会话不可恢复 |

6.4 输入、流式输出与消息反馈状态矩阵

| 状态 | 触发条件 | 页面表现 | 用户可操作 | 系统行为 | 异常处理 |
| 输入静默态 | 输入框无文字 | 展示占位文案；发送按钮不可用；语音入口可用 | 点击输入、长按语音 | 不请求 Agent | 无 |
| 文本输入中 | 输入框获得焦点且有文字 | 拉起系统键盘；发送按钮点亮；输入框最高 5 行 | 编辑、发送、清空 | 本地保存草稿；最大 1000 字符 | 达到上限后禁止继续输入并显示字数提示 |
| 消息发送中 | 点击发送 | 用户消息立即进入消息流；输入框清空 | 继续查看页面 | 创建消息、调用 Orchestrator | 发送失败时在消息旁显示重试 |
| AI 生成中 | 服务端开始流式返回 | 文字按打字机效果输出；发送按钮切换为停止按钮 | 停止生成、滚动查看 | 持续接收流式事件；先文字后卡片 | 断流时保留已生成内容并提供重试 |
| 用户停止生成 | 点击停止按钮 | 停止追加内容；对话流显示 Generated paused | 重新输入并发送 | 取消当前生成请求并保存停止原因 | 取消请求失败时客户端停止渲染并记录埋点 |
| AI 回答完成 | 收到完成事件 | 展示完整消息、引用标签、复制、点赞、点踩 | 复制、反馈、继续追问 | 保存最终消息、来源、模型版本和耗时 | 引用加载失败时隐藏链接但保留回答风险标识 |
| 复制成功 | 点击复制 | 弹出 Copied successfully Toast，1 秒消失；图标显示选中态 | 无 | 写入系统剪贴板并记录事件 | 剪贴板权限失败时提示复制失败 |
| 点赞成功 | 点击点赞 | 点赞图标实心；显示肯定 Toast | 取消或保留点赞 | 保存反馈 | 保存失败静默重试 |
| 点踩反馈 | 点击点踩 | 点踩图标实心并打开反馈问卷 | 选择原因、提交、关闭 | 按消息 ID 保存问题类型和补充内容 | 提交失败保留填写内容并允许重试 |
| 语音录制 | 长按语音键 | 展示录音反馈和时长 | 松开发送、上滑取消 | 请求麦克风权限并采集音频 | 无权限时展示系统权限引导；转写失败时允许重试 |

6.5 快捷 Chips 与结构化任务卡状态矩阵

| 状态 | 触发条件 | 页面表现 | 用户可操作 | 系统行为 | 异常处理 |
| Chip 静默态 | 当前 Session 未执行该任务 | 展示默认样式 | 点击 Chip | 以用户身份发送固定路由文案 | 无 |
| Chip 进行中 | 点击 Lactation Plan、Voice Log、BB Sleep Forecast 或 IBCLC | Chip 点亮；消息流插入对应任务卡 | 填写、提交、取消 | 100% 路由到约定 Agent；绑定 Session ID 和任务 ID | Agent 超过 5 秒未响应时插入兜底消息并恢复静默态 |
| Chip 已完成 | 对应工具卡提交成功 | Chip 显示完成态；卡片显示已保存结果 | 查看结果、继续对话 | 更新业务记录并触发 Forecast 刷新 | 状态回调丢失时根据任务查询结果修正状态 |
| 任务取消 | 用户中途退出任务卡 | 当前 Session 内保留进行中提示或恢复静默，按具体任务定义 | 重新进入 | 保存草稿或取消任务 | Session 结束后统一恢复静默态 |
| 功能不可用 | 子 Agent 未接入或 Feature Flag 关闭 | Beta 环境隐藏对应 Chip；MVP 联调环境可显示占位态 | 联调环境可点击验证 | 根据配置决定是否发起占位流程 | 不向真实用户展示不可用入口 |
| Pumping Log 待补充 | 用户只提供总吸乳量 | 展示左右侧输入卡片 | 输入 Left / Right 并保存 | 校验左右量与总量关系 | 数据不一致时提示用户确认，不自动篡改 |
| 工具保存成功 | 结构化卡片提交成功 | 展示成功状态和结构化结果 | 查看、继续追问 | 写入日志系统、回传 Chip 完成状态 | 保存失败保留字段并显示重试 |

6.6 Forecast 状态矩阵

| 状态 | 触发条件 | 页面表现 | 用户可操作 | 系统行为 | 异常处理 |
| 冷启动空态 | 用户没有有效 Pumping Log 或 Sleep Log | 在 What's coming up next? 下拉区展示 We are still learning your rhythm 静默信息 | 可展开 / 收起；无主动 CTA | 不生成虚假预测，不展示预测摘要或预测条目 | 无 |
| 收起态 | 接口返回有效预测，默认进入页面 | 展示 What's coming up next? 和最近一条预测摘要 | 展开、进入对应任务 | 每次进入页面请求一次 | 无 |
| 展开态 | 点击 Forecast 组件 | 展示全部吸乳和睡眠预测时间线、置信度和说明 | 收起、进入记录或计划 | 使用设备本地时区渲染 | 单条数据缺失时只隐藏该条目 |
| 记录后刷新 | 用户完成吸乳或睡眠记录并返回对话页 | 显示刷新后的预测 | 查看预测 | 触发一次预测接口请求，不轮询 | 刷新失败保留旧数据并标记更新时间 |
| 低置信度 | 预测服务返回低置信度 | 使用模糊时间范围，并提示仍在学习 | 继续记录 | 不展示精确到分钟的确定性结论 | 无 |
| 服务异常 | 接口超过 3 秒或返回错误 | 本次静默隐藏 Forecast 组件 | 正常聊天 | 记录超时和错误埋点，下次进入重试 | 不弹窗、不打断对话 |
| 功能未启用 | Forecast Feature Flag 关闭 | 不展示组件 | 无 | 不请求预测服务 | 无 |

6.7 医疗安全、RAG 与人工转接状态矩阵

| 状态 | 触发条件 | 页面表现 | 用户可操作 | 系统行为 | 异常处理 |
| 普通常识回答 | 问题属于批准知识范围且无风险 | 展示分段回答、信源标签和非医疗建议声明 | 打开引用、反馈、继续追问 | Orchestrator 路由至对应 Agent 或通用 RAG | 无可靠来源时降低回答范围或转人工 |
| RAG 有效命中 | 检索到已审核且适用的文档 | 回答后展示文档名称、章节或链接 | 查看引用详情 | 保存 Citation ID、文档版本和检索分数 | 引用页面不可用时保留文档信息并记录错误 |
| RAG 无有效命中 | 无文档、文档过期或相关度不足 | 明确说明无法确认，不生成确定性答案 | 转人工、换一种问法 | 阻止模型基于常识补全高风险内容 | 转人工服务不可用时提供官方联系方式 |
| 医疗红旗 | 命中发热、呼吸困难、意识异常、严重出血等规则 | 停止常规建议，突出展示立即联系专业医疗人员的提示 | 联系医生、急救或转人工 | 路由前和回答后各执行一次安全检测；阻断普通子 Agent 回答 | 安全服务异常时按高风险保守策略处理 |
| 情绪危机 | 检测到自伤、伤害婴儿、极端绝望等信号 | 使用支持性文案并展示当地紧急援助路径 | 联系紧急服务、可信任的人或人工支持 | 提升最高风险等级并记录受限审计日志 | 不让普通客服话术替代危机响应 |
| 低置信度转人工 | Agent 置信度低于上线阈值或连续失败 | 说明暂时无法可靠回答并提供人工入口 | 转人工、继续补充信息 | 生成问题摘要、已有信息、风险标签和已执行步骤 | 人工服务离线时创建待处理工单 |
| 设备复杂问题 | 涉及硬件损坏、过热、异味、保修或多次排障失败 | 提示停止危险操作并进入设备客服流程 | 创建工单、查看官方指南 | 转设备支持并附带设备型号和排障记录 | 无设备信息时先请求用户补充 |
| 投诉或维权 | 识别退款、隐私投诉、产品责任等诉求 | 不继续普通育儿咨询，展示对应客服渠道 | 转客服、提交工单 | 路由至人工客服并保留完整上下文 | 工单失败时提供官方备用联系方式 |

6.8 状态矩阵评审与验收要求

1. 产品、设计、客户端、后端、Agent、QA 和合规需在开发前共同确认 P0 状态；
2. 每一个状态必须具备唯一状态标识，便于接口返回、客户端渲染和埋点统计；
3. 所有加载、空态、成功、失败、超时、取消和重试状态均需有设计稿或使用设计系统中的标准组件；
4. QA 应基于本章节生成测试用例，并覆盖前后台切换、杀进程、弱网、重复点击、跨日、时区变化和 Session 过期；
5. 医疗风险、隐私授权、数据删除、记忆持久化和转人工流程必须单独通过合规验收；
6. 状态矩阵发生变更时，需同步更新接口契约、埋点定义、测试用例和原型标注。
